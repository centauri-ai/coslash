Finding the Session

Three answers to "I can't find the session I want, fast." The board stops being a sparse repo × status matrix; a table view handles the 52-row reality; and a ⌘K palette makes retrieval fast when you already know roughly what you're looking for.

Revised after Codex review. Changes in v2:
  • Search relevance now outranks live activity. v1 pinned Active sessions above results "regardless of rank", which buries the historical session you're actually hunting. Live shortcuts now appear only on an empty query; once you type, ranking is by match evidence with recency as tie-breaker.
  • Every result says why it matched — a field label plus the highlighted text.
  • Search scope is explicit, with one-click widening on thin results.
  • Empty lanes have defined behaviour — the claim "lanes are populated by construction" was overstated: the observed dataset had zero Waiting. Lanes hold fixed order and position and explain themselves when empty.
  • Idle and Unknown have their own lanes. v1 had nowhere to put either.
  • Empty-cell hatching removed — it added visual noise without information.
  • Resume names its destination (agent + machine) and respects launch eligibility.
  • prefers-reduced-motion honoured.
Data provenance. Counts and sessions are from the live local dataset on 2026-09-10 (52 sessions · 2 Active · 41 Inactive · 9 Unknown · 0 Waiting). Waiting and Idle examples are illustrative and labelled as such — neither was observed at inspection time.

A · Attention lanes — the board, re-asked

Why today's board is hard to navigate: it's a grid of repo × status with grid-template-columns: repeat(n, minmax(0, 1fr)) — every status column gets equal width regardless of population. With 2 Active, 41 Inactive and 9 Unknown, roughly two thirds of the horizontal space is permanently blank while 41 cards queue single-file down one narrow column. Only the status header is sticky, so scrolling 400px loses all repo context.

Lanes are ordered by demand on your attention and hold fixed position and order — they never reorder or disappear on refresh. Repo is a sticky subhead inside each lane, so context travels with the cards. Each lane scrolls independently.

V2 · FROM REVIEW

Lanes can be empty, and that's designed

The v1 claim that lanes are "populated by construction" didn't survive contact with the data — zero sessions were Waiting. Lanes now hold fixed order, position and width, and an empty lane states its own meaning rather than vanishing and reflowing the board.

V2 · FROM REVIEW

Idle and Unknown have homes

v1's four lanes had nowhere to put idle or the 9 unknown sessions. Unknown now gets a lane that explicitly says liveness couldn't be read and these are not finished.

V2 · FROM REVIEW

Hatching removed

v1 hatched empty matrix cells. On reflection that adds texture without information — an empty cell already reads as empty. Plain ground, no pattern.

V2 · CONSEQUENCE

Six lanes don't fit — so empty ones collapse

Giving Idle and Unknown their own lanes pushed the count to six, which overflows at 1280px. Rather than clip, populated lanes get a 208px floor and share remaining width, while zero-count lanes collapse to a 150px strip that keeps its position. Beyond that the board scrolls horizontally. This is the honest cost of representing every status.

FIX

Repo context travels with the cards

Repo is a sticky subhead inside each lane rather than a full-width row above the grid, so the repo you're reading is always pinned at the top of its column.

FIX

Columns scroll independently

Today the whole grid is one scroll surface, so reading the 41-card Inactive column drags the live sessions off screen. Per-lane scroll keeps them visible. Tradeoff noted in review: more scroll targets, so keyboard lane-switching needs a real design.

ADD

The lane axis is a control

"Lanes by Attention / Status / Repo / Agent" turns one hard-coded board into four. Users who prefer the status board keep it.

B · Table view — for when there are 52 of them

Cards are right for ten sessions and wrong for fifty. Sortable columns make "the expensive one from yesterday" two clicks instead of a scroll hunt.

C · ⌘K — retrieval, with evidence

Why search misses today: sessionMatchesSearchTerm tests exactly three fields — name, repo, branch. Verified live: searching Frosty returns "Nothing matches" while the card reading "Selected Laticrete Frosty as the recommended grout color…" is visible in the same window. Searching Laticrete returns three results, one of which matched only because its repo is the generated folder compare-https-www-laticrete-com-products — with nothing on screen explaining why.

Broader indexing and match evidence have to ship together — adding outcome and filename matching without showing why a result matched makes the confusing-result problem worse, not better.

V2 · FROM REVIEW

Relevance beats liveness once you type

v1 pinned live sessions to the top "regardless of rank". An unrelated running session should never precede an exact outcome match. Live and recent shortcuts now belong to the empty-query state only.

V2 · FROM REVIEW

Every result shows its evidence

A field label (outcome, goal, repo) plus highlighted text. The Laticrete false-friend now explains itself: matched on a generated folder name, flagged as such.

V2 · FROM REVIEW

Coverage gaps are disclosed

Sessions with pending or missing synthesis are listed as explicitly not searched, rather than silently absent. This was the review's core objection to treating "two lines of code" as the acceptance criterion.

V2 · FROM REVIEW

Scope is stated, not assumed

A scope bar names the time window, agent and machine constraints with the match count, plus one-click widening — instead of the current empty state suggesting a window change that cannot help.

V2 · FROM REVIEW

Resume names its destination

⌘↵ shows which agent and machine it would launch into, targets the visibly selected row, and disables itself where resumeDisabled applies rather than failing after the keystroke.

OPEN

Still unvalidated
